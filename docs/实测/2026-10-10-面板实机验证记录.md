## 三、发现与处置（F1–F11）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| **F1** | 改写一条**嵌在 `- insert: [...]` 里**的手写行后，配置出现在 profile patch **末尾**，而不是原行上 | 官方配置编辑服务**只认顶层 `- id:` 行、明确排除 `insert` 行**（`packages/boot/config-editor/src/index.ts:117-128`）⇒ 它只能"追加一条顶层覆盖行" | 采纳为**既定行为**；面板加 `已覆盖` 标记与「撤销覆盖」按钮（见 [ADR 0001](../adr/0001-两层文件与两条写回路径.md)） |
| **F2** | 早期文档把 `profiles/<profile>/cordis.patch.yml` 写成"只读" | 与 F1 不符（官方通道的写入落点就是它） | 已订正：明说"本插件不直接改写，但官方写入落点就是它"，并补"改 `insert` 不生效需先撤销覆盖"的后果提醒 |
| **F3** | 经覆盖行改写 `url` 后，该行**确实重连**并注册出新工具 | 覆盖行在文件内更靠后 ⇒ 优先级更高 ⇒ 生效 | **链路（覆盖 → 热重载 → 重连）判定为全通** |
| **F4** | **三级 id 冲突检测的第三级**（手写层文本弱扫）当时**没有实现** | 实现遗漏 | 冒烟测试当场抓出 ⇒ 已修：同时扫自有层与手写层，**只取 id、不带出正文** |
| **F5** | 面板"服务名下注"过长；掩码里带"共 N 字符" | 两个展示层取舍 | 注文改为「原手写行」；掩码改为 `协议//主机/…`（**不再透露长度**） |
| **F6** | 状态列**三行全显示**"挂载 / 重连中" | 官方清单字段名是 **`fiberPhase`**（取值 `pending/loading/active/failed/unloading/null`），而 cordis 的 `FiberState` 是**数字 const enum**（`ACTIVE = 2`）⇒ 早先按字符串匹配**全部落空**，读不到就退化成"加载中" | 已修：优先读 `fiberPhase`；退回路径改**数字→语义**映射表；未知值返回 `unknown`，**不再伪装成"加载中"** |
| **F7** | 状态口径不可读 | 原口径是内部阶段名 | 改成大白话五档（已启用 / 已启用·未发现工具 / 已启用·加载中 / 已禁用 / 加载失败 / 未加载 / 配置冲突）；工具数收进悬停提示；顶部备注重写，并**直接显示受管行的写入路径**（消除"我改的到底是哪个文件"的歧义，即 F8） |
| **F8** | 在 `profiles/<profile>/cordis.patch.yml` 里**找不到**刚新增的行 | **非缺陷**：受管行按设计写在 `$DSH_HOME/cordis.patch.yml`（自有层），不在 profile patch | 面板顶部现在直接显示该路径；`list` 回传 `paths.homePatch` 供核对 |
| **F9** | 早期版本面板备注里出现**含用户名的绝对路径** | 回传时未做符号化 | 已修：**回传给浏览器的一切路径符号化**（按 `$DSH_HOME` 前缀裁剪）；单测新增断言"回传载荷不得含绝对主目录路径" |
| **F10** | 一度把"资源服务器清单里出现该服务器"当作连接成功的**旁证** | 订正：`registerServerContext` 在 **connect 之前**调用（`packages/mcp/mcp-client/src/server-context.ts:28-39`），且连接失败也不会移除共享工具 | **口径订正为**：清单出现 = **行已挂载**；**工具出现 = 连接成功过的唯一可靠证据**。状态列因此以**工具数**为准 |
| **F11** | 某行长期显示「已启用 · 未发现工具」，调任何工具都报 `server is disconnected` | **宿主侧协商模式**：宿主把 `versionNegotiation` 设为 `{ mode: 'auto' }` ⇒ 连接前先发 `server/discover` **探测**；**某些服务端对该探测回 HTTP 5xx**，而客户端库把 5xx 判为**致命、不回退旧版握手**（4xx 或 JSON-RPC error 才会回退）⇒ 该行永久连不上 | 判据：宿主日志出现 `Version negotiation failed: the server answered the probe with HTTP <5xx>`。处置在**宿主侧**（该库的默认模式本就是 `legacy`）；**与本面板无关**，但面板的「未发现工具」正是它的可见症状 |

> F11 是 2026-10-11 追加的**宿主侧**发现，记在此处是因为它**与面板的状态口径直接相关**：
> 面板显示「已启用 · 未发现工具」时，除了"服务端确实没有工具"，还有这一条**宿主侧**可能。

## 四、遗留与未取得（诚实列出）
